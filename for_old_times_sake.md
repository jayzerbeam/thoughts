# For Old Times Sake

I've been working on a personal coding project lately, as an experiment I decided to write a bunch of features old school vs new school.

One set of features coded strictly by hand, no LLMs outside of helping looking up docs. The other set of features developed largely agent driven, my involvement with code almost exclusively review.

I figured I already had a good grasp on the difference and what to expect being a coder through the AI renaissance/apocalypse, even still, I was surprised. Development now does not feel remotely like it used to.

## Old School

*"Qui scribit, bis legit"*.
	- old Latin maxim

Not to be overly tautological, but one needs to know how to code in order to write code. Not only is skill required in the first place but the exploratory nature of coding builds skills as well as a deep understanding of what the code is doing.
Blind spots overlooked during planning are naturally encountered as the implementation is built, ambiguities are resolved, every decision must be thought through and is deliberate.
As the maxim states: *"he who writes, reads twice"*

There's a certain zen when the mental flow state is reached, your concentration is focused, you know the solution, there's no distractions, and code is flowing straight from your brain through the keyboard.

## New school

Agent driven is not remotely the same thing. I'm not writing code any more, I'm managing agents and reviewing code. There's so much code it's difficult to even review, so... more agents for that.

For well defined features in an organized codebase in a well put together system within the realm of my expertise the level of automation, and consequently velocity, is insane.

I dare say the quality of the code I can produce can be even higher. These LLMs are one of the best rubber ducks I've ever had. They don't compare with the knowledge and insight I get from conversing with an expert person but I don't know anyone who's available 24/7 for me to prod with questions, talk through ideas, and peruse through spaghetti code.

The context switching is unreal. Managing a fleet of agents and subagents churning through a dozen different tasks is entirely possible, and entirely mentally exhausting.

As an engineer we need to know how something will perform before we put it to use. LLMs don't exactly come with spec sheets. Determining which model may be best and most cost efficient doesn't have much more to go on besides *trust-me-bro* vibes. Sure, there's benchmarks, but models can be tuned to game them. The nature of LLMs are that they operate largely as a black box, and while some may be open-weight, we don't really know how any of them are trained or tuned.

Oh, and tokens can get damn expensive for some of these models.

# Hurm...

The nice thing about working with people is that most will realize their gaps in knowledge, and the ones that don't often raise some sus vibes. LLMs operate quite to the contrary, they speak convincingly with confidence.
There have been plenty of instances that I knew Claude was feeding me a line of crap only because it was well within my domain of expertise.

There's also one massive, striking irony I can't overlook... One of the most satisfying part of development is sitting down, writing code, and attaining programmer's zen. A vibe that "vibe coding" has effectively robbed from the process.

Fundamentally, our job as developers was never truly writing code, it's solving problems and building things. The start and finish remain similar but how we make the journey in between has changed dramatically.
